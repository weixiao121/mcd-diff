# 方案 v1.0 —— 「麦门 Diff」mcd-diff

> 从 `mcd-archaeologist` 继承全部工程基因，但在**产品立意上做 180° 反转**：
> 考古学家回答「**我做了什么**」，麦门 Diff 回答「**我本该做什么**」。

---

## 0. 先盘资产：考古学家留下了什么

`mcd-archaeologist`（v1.0 双账簿）已经跑通并沉淀了 6 项可复用资产：

| # | 资产 | 说明 | 复用情况 |
|---|---|---|---|
| 1 | **订单解析内核** | `collectors.py` + `metrics.py`：把 `order-list` / `query-order` 归一到统一订单结构 | ✅ 直接复用 |
| 2 | **营养 join** | `list-nutrition-foods` 一次拉取 + 单品名归一化本地 join | ✅ 直接复用 |
| 3 | **菜单层** | `menu.py` + `data/menu.json`：24 项单品的价格 / 热量 / 蛋白 / 钠 / **品类** | ✅ 直接复用 |
| 4 | **双约束求解器** | `solver.py`：全枚举精确最优，`max(蛋白质)` s.t. 预算 ∩ 热量 | ✅ **核心复用**（新增品类约束） |

**结论**：新项目**不需要重建任何底层**。它只是在同一套内核上，换一个**完全不同的问题**。

## 2. 为什么是这个：一个**反向的孔洞**

### 2.1 榜单的时态分布（数据源：56 项目快照）

| 时态 | 项目在回答的问题 | 代表 |
|---|---|---|
| **现在时** | 我**该**买什么？ | saver-strategist、nutrition-optimizer、budget-solver、easy-order …（≈20 个） |
| **过去时（聚合）** | 我**做了**什么？ | mcd-wrapped、mcd-persona-card、mcd-whoami …（≈6 个） |
| **过去时（反事实）** | 我**本该**做什么？ | **空 —— 全场 0 个** ⬅️ |

- **现在时**是红海：省钱 6 + 热量 7 + 积分 4 + 点餐 4，全是"下一单怎么下"。
- **过去时聚合**是小蓝海：`mcd-wrapped` / `persona-card` 已占位，但只有 1–7 Star —— **说明品类没被做好，不是没需求**。
- **过去时反事实（Counterfactual）是真空区**：没有任何项目对**已经发生的订单**做平行推演。

### 2.2 为什么这个孔洞值钱

省钱类在**下单前**给建议 → 用户当时不会信（"我就想吃巨无霸"）。
麦门 Diff 在**下单后**给复盘 → 用**你自己的真实订单**做靶子，**无法反驳**。

> 让人 star 的不是"你给我建议"，是"**你算出了一个我自己算不出来的、关于我自己的数字**"。

## 3. 核心机制：`实际值 − 重开值 = 差额`

### 3.1 定义

对历史订单中的**每一单 i**：

```text
输入：该单的实际构成（单品 × 数量）、实付金额 cost_i、摄入热量 kcal_i、蛋白 pro_i
约束（关键设计）：保持"同等条件"——以该单自身的实付 / 热量为上限
重开：在菜单中枚举 ≤4 件组合，求满足约束的最优替代方案
输出：optimal_cost_i / optimal_kcal_i / optimal_pro_i
```

```text
省钱差额   Δcost_i    = cost_i  − optimal_cost_i        （恒 ≥ 0，预算约束保证）
热量差额   Δkcal_i    = kcal_i  − optimal_kcal_i         （>0 表示本可以更少热量）
蛋白增益   Δprotein_i = optimal_pro_i − pro_i            （>0 表示同等条件下能吃得更扎实）
```

**年度封面数字**：

```text
可节省空间 = Σ max(0, Δcost_i)          → 「一年本可以省下 ¥279」
可减热量   = Σ max(0, Δkcal_i)          → 「一年本可以少吃 3,615 千卡」
```

### 3.2 为什么约束要"以该单自身为天花板"

这是全案最严谨的一处：

- 省钱类解 **"最小化价格"** → 必然推出"什么都别点最省"（荒谬）。
- 热量类解 **"最小化热量"** → 必然推出"只喝零度可乐"（劝人少吃，踩红线）。
- **我们锁定该单原有的"钱 & 热量"作为天花板**，只问：**同样的预算、同样的热量，能不能吃得更好？**
  - 既不**劝用户少花**（预算不变），也不**劝用户少吃**（热量不变）；
  - 输出的是**"更优解"而非"更省"**，天然规避价值判断与健康建议的合规风险。
- **自洽性**：预算上限 = 该单实付 ⇒ 重开价必然 ≤ 实付 ⇒ **Δcost ≥ 0 恒成立**，不需要任何裁剪。

### 3.3 三条重开路线（用户可选）

**约束完全相同，只有目标函数不同** —— 所以三种结果天然可对照。

| 路线 | 目标函数 | 会得到 | 实测（74 单） |
|---|---|---|---|
| **`--mode thrift` 省钱向**（默认） | 同热量下**最小化价格** | 「这顿本可以只花 ¥X」 | 省 **¥279（11.4%）**、减 3,615 kcal、蛋白 +88 g |
| `--mode balanced` 扎实向 | 双约束内**最大化蛋白质** | 「同样 ¥35 / 800 kcal，本可以多吃 9 g 蛋白」 | 省 ¥77、减 1,540 kcal、蛋白 **+369 g** |
| `--mode lean` 轻负担向 | 同预算下**最小化热量** | 「这顿本可以少 180 kcal」 | 省 ¥174、减 **8,525 kcal**、蛋白 +36 g |

> **默认走 `thrift`**：产品的核心钩子是"你本可以省下多少钱"，`balanced` 只省 3.1%，钩子太弱。
> 但三条路线**并排展示** —— 这张对照表本身就是产品价值：
> **"省钱"和"吃得扎实"是两件事**，而市面上所有工具都只给你一个答案。

## 4. 五大模块

### 模块 1 · ⏪ 重开橱窗（Replay Window）

报告顶部是**一单一单的平行对照**：左边"你实际点的"，右边"重开后的更优解"，中间是差额。

```diff
  #01  2026-09-20 12:18 · 杭州武林广场店
- 板烧鸡腿堡 · 玉米杯 · 雪碧(中) · 麦辣鸡翅(2块) · 麦乐鸡(5块) · 可口可乐(中) · 麦旋风
+ 安格斯厚牛堡 · 那么大鸡排 · 香芋派 · 可口可乐(中)
  ¥84.28 → ¥61.17    便宜 ¥23.11 · 少 100 kcal · 蛋白持平
```

### 模块 2 · 💸 差额账簿（Diff Ledger）

| 指标 | 示例值 |
|---|---|
| 可节省空间 | **¥279**（占全年 11.4%） |
| 可减热量 | 3,615 kcal |
| 蛋白净变化 | +88 g |
| 单均可省 | ¥8.2 |
| 重开潜力指数 | 28 / 100 |
| 有重开空间的单 | 34 / 74 |
| **已是最优的单** | **40 / 74**（正向激励，必留） |

### 模块 3 · 🧭 三条路线 + 📊 归因

归因按时段、渠道两维展开 —— 实测**深夜单**的可节省率最高（≈22%），远高于早餐（≈1%）。

### 模块 4 · 🏆 双排行榜

- **最值得重开 TOP 5**：`Δcost` 最大的五单
- **点得最漂亮的 TOP 5**：最接近最优的五单 —— 报告里**必须有一块是夸你的**，否则全是自责，传播会跑偏

### 模块 5 · 🌀 平行宇宙（Parallel You）

> 纯情感向的收尾，负责"被分享"。

把**重开后的订单集**重新送进 `persona.py`，与**现实的你**并列：

```text
现实宇宙：🌅 早餐先锋，年支出 ¥2,448，客单价 ¥33.1
平行宇宙：🌅 早餐先锋，年支出 ¥2,169，客单价 ¥29.3

你少花的 ¥279，相当于 8.4 顿麦当劳。
```

**最后一句话**（全案的情绪落点，也是合规保护）：

> **「我只改了数字，没改你的快乐。」**

## 6. 技术架构（复用度 ≈ 70%）

```text
┌── 本轮新增 ────────────────────────────────────────────┐
│  regret.py      差额引擎：批量求解 + 逐单归因 + 汇总统计  │
│  templates/diff.html   重开报告模板（diff 对照布局）      │
│  cli.py         diff / solve 两个子命令                  │
│  solver.py      require_categories 品类保留约束（扩展）   │
└────────────────────────────────────────────────────────┘
                ▲
                │ 调用
┌── 直接复用 mcd-archaeologist ──────────────────────────┐
│  collectors.py  订单采集与归一（含 assert_readonly）     │
│  metrics.py     时段 / 渠道 / 月度聚合                   │
│  menu.py        菜单层（24 项，含 category）             │
│  solver.py      双约束求解器（核心算法）                 │
│  persona.py     人格规则表                               │
│  renderer.py    渲染基座                                 │
└────────────────────────────────────────────────────────┘
```

**算法**：菜单 24 项 × 一餐 ≤4 件 = 12,950 组合/单。
对 N=74 单做全量重开 → 74 × 12,950 ≈ **96 万次组合枚举**，纯 Python 实测 **约 1.9 秒**。
**精确最优、零启发式、完全确定性、可单测。**

**架构一句话**：把求解器从"**用一次**"改成"**对一个订单集跑 N 次**"，其余全部照抄。

## 7. 落地过程中解决的四个技术难题

| # | 问题 | 现象 | 解法 |
|---|---|---|---|
| 1 | **品类被优化掉** | `猪柳蛋麦满分+鲜煮咖啡` → `猪柳蛋麦满分`（省 ¥12，但咖啡没了） | 新增 `require_categories` 品类保留约束；**用户想喝咖啡，但不必喝这一杯** |
| 2 | **大面积不可行** | 41/74 单"无解" | 实付含优惠、菜单是原价 → 按该单折扣系数缩放菜单，**可解率 45% → 100%** |
| 3 | **浮点容差假不可行** | 修复 #2 后仍有 5 单无解 | `round(price*factor, 4)` 让原组合略超预算 → **刻意不 round**，并放宽自设的蛋白下界 |
| 4 | **默认路线钩子弱** | `balanced` 只省 3.1% | 实测三模式后改为 `thrift`（11.4%），`balanced`/`lean` 作为并排对照保留 |

## 9. 合规与安全边界

| 红线 | 本方案的处理 |
|---|---|
| 不得宣扬不健康饮食 | 约束**锁定该单原热量**，不鼓励"越低热量越好"；`lean` 路线明确标注为"同等预算下的机械换算"，非健康建议 |
| 不得做健康 / 营养建议 | 全部输出为**机械换算与陈述**；报告底部固定免责声明 |
| 不得贬低品牌 / 跨品牌对比 | 数据只来自麦当劳自有渠道；情绪落点是**「好吃才值得」**，是正向的 |
| 不得劝用户少消费 | **预算上限 = 该单实付金额**，重开不降低消费额，只提高"同等消费下的获得" |
| 信息安全 | Token 仅走环境变量；示例数据为程序生成虚构数据；配置示例仅占位符 |
| 只读边界 | **不调用** `create-order` / `cancel-order` / `calculate-price` / `draw-lottery` / `party-order-create` / `mall-create-order` / `auto-bind-coupons`；`assert_readonly()` 硬拦截 |

> ⚠️ 一条需要额外说明的红线：**"后悔"这个词对品牌有潜在风险**。
> 处理方式：全案对外文案统一包装为 **「重开 / 平行宇宙 / 为快乐付的溢价」**，
> **刻意不使用"后悔"二字作为对外主文案**，只在内核（`regret.py`）保留该命名。

## 10. 与考古学家的关系

| | mcd-archaeologist | mcd-diff |
|---|---|---|
| 隐喻 | 考古 · 挖出过去 | Diff · 改写过去 |
| 时态 | 过去（聚合） | 过去（反事实） |
| 输出 | 两本账簿 | 一份平行对照表 |
| 情绪 | 怀旧 · 认同 | 自嘲 · 释然 |
| 共享内核 | 订单解析 · 营养 join · 求解器 · 人格 · 渲染 | ← 同一套 |

**决策（受规则约束）**：

> 赛制规定：**同一 GitHub 账号多个项目，只有 Star 最高的一个进榜。**

因此：**二选一上架** —— `mcd-diff` 作为主项目；`mcd-archaeologist` 转为 `Related / 灵感来源`，
两仓库互链形成"系列作品"的品牌感，并可反哺 Star。

**为什么选 `mcd-diff` 当主项目**：它的钩子只有**一个数字**（本可以省 ¥279），
比"两本账簿"更短、更易传播；且 `diff` 这个词本身就自带程序员受众的会心一笑。
