# 仓库命名决策 —— mcd-diff · 麦门 Diff

> 产品做的事：**把过去每一单重新点一遍，算出差额。**
> 名字要能在 0.5 秒内让人明白"这是干什么的"，并且在 3 秒内让人想点 Star。

---

## 1. 取名标准（四条，按权重排序）

| # | 标准 | 说明 |
|---|---|---|
| 1 | **受众匹配** | 本赛是「**程序员**创意开发大赛」，早期 Star 主要来自技术社区（掘金 / 知乎 / GitHub）。名字要能让程序员**会心一笑** |
| 2 | **自解释** | 看到名字 + 一行副标题就能懂产品，不需要读 README |
| 3 | **短、好拼、好记** | 要进 URL、进徽章、进一句话分享。≤2 个音节最佳 |
| 4 | **能承载情绪** | 产品落点是"我没有重开，因为好吃"——名字要留出这个转折的空间 |

> ⚠️ 一条排除项：**不用"后悔 / 悔"字**。对品牌有负面联想风险，赛制有「不得贬低品牌」红线。

## 3. 最终推荐

### 🥇 主推：`mcd-diff` · 麦门 Diff

**副标题**：把你的麦当劳账单，跑一遍 diff。

**四条标准全部命中**：

| 标准 | `mcd-diff` 的表现 |
|---|---|
| 受众匹配 | ✅ `diff` 是程序员的**日常动词**，看到就知道"这是对比两个版本" |
| 自解释 | ✅ 报告本身就是一份 diff：`- 你点的` / `+ 本可以点的` |
| 短好记 | ✅ 4 个字母，一个音节，URL 干净 |
| 情绪留白 | ✅ diff 是**中性的、技术的**——不指向品牌（合规安全），且天然引出"我只改了数字，没改你的快乐" |

**杀手锏：README 第一屏可以直接用真 diff 语法渲染。**

```diff
  2026-03-12  上海南京西路店
- 巨无霸           ¥25
- 中薯条           ¥16
+ 双层吉士汉堡      ¥20
+ 玉米杯           ¥12
  ────────────────────────────
  ¥41 → ¥32      省下 ¥9 · 少 20 kcal
```

**在 GitHub 上，这段会渲染成红绿配色** —— 程序员扫一眼就懂了，比任何一段文字介绍都快。
**这就是命名带来的免费传播资产。**

---

### 🥈 备选一：`mcd-whatif` · 麦门假如

大众传播力最强。「假如当初……」是所有人都会用的句式，漫威《What If...?》给了它流行文化光环。
**短板**：新意中等，梗已被用得较多；不如 `diff` 精准对上"程序员大赛"的受众。

### 🥉 备选二：`mcd-ng-plus` · 麦门二周目

游戏梗里最好的一个。"二周目"= 带着一周目的经验重打一遍，**语义完全吻合**（带着历史订单重算）。
**短板**：`ng-plus` 进 URL 略长；"二周目"需要一点游戏经历。

### 🎁 彩蛋：`mcd-ctrl-z` · 麦门撤销

最短最狠的那个。如果只面向程序员受众，它是 `diff` 之外的唯一答案。
