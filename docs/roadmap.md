# Roadmap

> 原则：**每一版都必须让"可验证性"变强，而不是让"建议变得更多"。**

---

## v1.0 — 差额引擎 + 重开报告（已完成，当前版本）

- [x] `regret.py`：**差额引擎** —— 逐单重开 → `Δcost / Δkcal / Δprotein` → 年度汇总 + 两维归因 + 双排行榜
- [x] **三条重开路线**（约束相同、只换目标函数）：`thrift` 省钱向（默认）/ `balanced` 扎实向 / `lean` 轻负担向
- [x] `solver.py` **结构保留约束**：`require_categories`（品类齐全）+ `require_category_counts`（**份数对得上**）—— 不做"把饮料删掉"式的伪优化
- [x] **折扣系数口径对齐**（`_price_factor` → `Constraints.price_factor`）：让「重开价」与「实付」可比，可解率 45% → **100%**
- [x] **性能：66 秒 → 4.9 秒**（组合表按菜单指纹缓存 + 按目标预排序 + 缩放系数下沉到约束层，结果逐位相同）
- [x] `scripts/collect.py`：**自带标准库 MCP 客户端**，零第三方依赖、开箱即跑（手写 `initialize` → `tools/call`，兼容裸 JSON 与 SSE 响应）
- [x] `data/menu.json`：由 `collect.py` 从 MCP **实拉的 41 项真实单品**（多时段探测合并：早餐品项只有清晨那轮才拉得到；真价格、真营养，未做人工调整）
- [x] 🌀 **平行宇宙**：把重开后的订单集重新送进人格引擎，与现实并排对照
- [x] `renderer.py` + `templates/diff.html`：自包含 HTML（零依赖、离线、纯 CSS/SVG）/ Markdown / JSON 三种输出
- [x] `cli.py`：`diff`（主）与 `solve` 两个子命令
- [x] 差分解释器：`- 你点的` / `+ 重开的` / `Δ 差额`，GitHub 自动红绿渲染
- [x] `examples/generate_sample_data.py`：固定随机种子的**虚构订单**生成器（74 单，组合自真实菜单）
- [x] **22 项单元测试**（含 Δcost ≥ 0 不变量、结构保留、热量不增、不可行不崩溃、0 元单不虚报、只读边界）

**实测（示例数据，74 单，`--mode thrift`）**

```text
💰 ¥2660 → ¥2289      本可以省 ¥371（14.0%）
🔥 本可以少 5162 kcal  ｜ 🥩 蛋白 +161 g
⏪ 有重开空间 61 单 ｜ 🎯 已是最优 13 单 ｜ 潜力指数 35/100
耗时 ≈ 4.9 秒（41 项菜单 / 112,791 组合，组合表只构建一次）
```

## 明确不做的事

- ❌ **不做交易**（下单 / 支付 / 取消 / 抽奖 / 积分兑换）
- ❌ **不上传任何用户数据** —— 采集数据只写本地 `.mcd-diff/`，报告离线生成
- ❌ **不做健康或营养建议** —— 只做机械换算与陈述，且热量上限定为该单自身实际值
- ❌ **不做「省到极致」的优化** —— 不做"把饮料删掉"式伪优化，**结构保留**约束优先于省钱
- ❌ **不用「后悔」二字作为对外文案** —— 统一包装为「重开 / 平行宇宙 / 为快乐付的溢价」
- ❌ **不做跨品牌对比、不贬低任何品牌**
- ❌ **不做用户间数据共享** —— 对比功能也只在本地文件间进行
- ❌ **不为了功能数量牺牲可验证性** —— 每一版新增的输出，都必须能被用户用同一套规则复算
